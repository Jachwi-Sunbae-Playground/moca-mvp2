## 사진 객체 불일치 대응

- `PHOTO_UPLOAD_FAILED`와 함께 보상 삭제 실패 로그가 있으면 request ID와 발생 시각으로 범위를 좁히고, 접근이 제한된 운영 도구에서 해당 시각의 객체 저장소 변경과 DB `property_photos` 메타데이터를 대조한다. 로그나 공유 문서에서 내부 storage key를 찾는 절차를 전제하지 않는다.
- DB 메타데이터가 없고 고아 객체가 확인되면 요청·회원 정보와 내부 key를 장애 기록에 추가하지 않고 승인된 운영 절차로 해당 객체만 수동 정리한다.
- `PHOTO_DELETE_FAILED`이면 DB 매물·사진을 먼저 삭제하지 않는다. `deleteIfExists` 재시도가 안전하므로 같은 삭제 흐름을 다시 실행하고 외부 객체 삭제 완료 뒤 DB 삭제 여부를 확인한다.
- 장애 기록과 공유 문서에는 사진 바이너리, 원본 파일명, 객체 저장소 자격증명과 공개 가능한 링크를 남기지 않는다.
