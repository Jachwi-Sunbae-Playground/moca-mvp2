# 모니터링

- 상태: 초안
- 현재 제공 항목: Actuator health, 요청 추적 로그
- 외부 모니터링·알림 도구: 미정

## 관찰 대상

- 가용성: health 상태와 요청 성공 여부
- 오류: HTTP 5xx, 대표 비즈니스 오류와 예외 발생량
- 성능: 요청 지연시간, 느린 쿼리와 DB 연결 상태
- 자원: CPU, 메모리, 디스크와 커넥션 풀
- 제품: 지정 요구사항 2에서 정한 사용자 행동 지표
- 사진 정합성: `PHOTO_UPLOAD_FAILED`, `PHOTO_READ_FAILED`, `PHOTO_DELETE_FAILED`와 업로드 보상 삭제 실패 로그

## 원칙

- 알림은 담당자가 행동할 수 있는 조건에만 설정한다.
- 로그에 비밀번호, 토큰, 개인정보와 전체 요청·응답 본문을 남기지 않는다.
- 관찰하려는 질문과 판단 기준을 수집 전에 정한다.
- 사실로 관찰한 값과 팀의 해석을 구분해 기록한다.

## 요청 추적 로그

- 응답의 `X-Request-Id`와 로그의 request ID로 한 요청을 추적한다.
- 안전한 형식의 `X-Request-Id`만 이어 쓰고 나머지는 서버가 UUID를 생성한다.
- 요청 메서드, query string을 제외한 경로, HTTP 상태와 소요 시간만 기록한다.
- Authorization 헤더, 요청·응답 본문, Google code·token·nonce, 자취선배 JWT, 이메일과 표시 이름은 기록하지 않는다.
- 사진 원본 파일명·바이너리·Content-Type·내부 storage key는 기록하지 않는다. 업로드 DB 단계와 보상 삭제가 모두 실패하면 request ID, 안전한 예외 유형과 실패 단계만 기록하고 제한된 운영 도구로 객체 저장소와 DB를 대조한다.

도구를 선택할 때 보존 기간, 비용, 접근 권한과 알림 채널을 함께 결정한다.
