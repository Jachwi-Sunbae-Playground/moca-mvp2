# 2026-08 1차 실험: 랜딩페이지 메시지·모집 검증 + 팀원 직접 현장 검증

- 상태: 설계
- 관련 가설: [메시지 가설](../product/hypotheses.md)

## 목적

랜딩페이지는 현장 사용성과 반복 사용을 검증하지 않습니다. 다음 두 가지만 확인합니다.

1. `짧게 보고 놓친 문제가 2년 동안 반복된다`는 메시지가 실제 집 탐색자에게 문제로 인식되는가
2. 임장을 위한 추가 정리된 체크 자료를 요청하는가

## 랜딩 메시지 구조

```
집은 10분 보고, 2년을 산다
→ 소음·수압·곰팡이·관리비·하자·계약 조건을 놓쳤을 때의 구체적인 결과
→ 꼼꼼한 사람이 아니어도 5분이면 핵심을 확인할 수 있음
→ 5개 항목 즉시 체험
→ 전체 체크 자료 요청 또는 현장 베타 신청
```

대표 문구는 다음과 같습니다.

> **집은 10분 보고, 2년을 삽니다.**
>
> 어디서 찾은 집이든 자취선배에 담고, 꼭 볼 것만 5분 확인하세요.

## 팀원 직접 현장 검증

랜딩페이지 실험과 병행하여 팀원이 직접 첫 번째 사용자가 되어 실제 매물 확인 과정에서 와이어프레임과 체크리스트를 사용합니다.

이 활동의 목적은 외부 사용자의 수요를 증명하는 것이 아니라, 외부 현장 실험 전에 다음을 확인하고 MVP를 개선하는 것입니다.

- 실제 임장 중 체크리스트를 사용할 수 있는가
- 핵심 항목을 5분 안에 확인할 수 있는가
- 중개인의 설명을 들으면서 화면을 조작할 수 있는가
- 체크 때문에 임장 흐름이 끊기거나 눈치가 보이지 않는가
- 체크만으로 충분한지, 메모·사진·음성 기록이 필요한가
- 여러 매물을 본 뒤 기록을 구분하고 비교할 수 있는가

## 진행 방법

1. 팀원별로 실제 매물 3~4개를 확인합니다.
2. 가능한 범위에서 원룸·고시원 등 서로 다른 주거 유형을 확인합니다.
3. 모든 팀원이 동일한 와이어프레임 또는 체크리스트를 사용합니다.
4. 검증할 가설과 관찰 항목을 임장 전에 작성합니다.
5. 임장이 끝난 직후 사용 시간, 누락한 항목, 불편했던 순간과 추가로 필요했던 기록을 작성합니다.
6. 여러 팀원에게 공통으로 발생한 문제와 개인에게만 발생한 문제를 구분합니다.
7. 결과를 바탕으로 체크 항목, 순서, 화면과 기록 방식을 수정합니다.

## 판단과 활용

- 5분 안에 완료하기 어렵다면 항목과 화면을 줄이거나 `5분 확인` 가설을 수정합니다.
- 다른 메모장이나 카메라 앱을 반복해서 사용한다면 현재 기록 방식이 충분하지 않은 이유를 확인합니다.
- 팀원도 현장에서 사용하지 않거나 가치가 낮다고 느낀다면 외부 사용자를 모집하기 전에 핵심 기능과 가설을 다시 검토합니다.
- 팀원 검증 결과는 외부 사용자의 수요를 입증한 결과로 해석하지 않습니다. 현장에서 발생하는 사용성 문제를 빠르게 발견하고, 2차 외부 사용자 MVP 실험의 완성도를 높이기 위한 사전 검증으로 사용합니다.
