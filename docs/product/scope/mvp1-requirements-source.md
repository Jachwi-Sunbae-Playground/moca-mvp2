# MVP1 전달 요구사항 원문

- 문서 성격: 시점 고정
- 갱신 정책: 2026년 8월 24일 사용자가 전달한 MVP1 범위·요구사항·정책을 보존하므로 수정하지 않습니다

## 문서의 위치

이 문서는 MVP2를 설계할 때 참고할 **MVP1 의도와 정책의 전달본**입니다. 내부에 서로 충돌하는 문장이 있더라도 원문의 의미를 보존합니다. 실제 구현 사실은 [`mvp1-baseline.md`](mvp1-baseline.md), MVP2에서 채택한 정책은 [`../decisions/README.md`](../decisions/README.md)를 따릅니다.

## 1. MVP 범위

### 포함

- Google 로그인과 로그인 상태 유지
- 회원 정보 조회와 로그아웃
- 후보 매물 관리
- 매물 사진 관리
- 메모와 자유 메모 관리
- 시스템 핵심·선택 체크 항목 제공
- 사용자 체크리스트 관리
- 매물 단계별 체크리스트 적용과 교체
- 체크 상태·항목 메모 자동 저장
- 단계별·매물 전체 진행 현황 제공

### 제외

- 사용자 간 체크리스트 공유
- 사용자가 새로운 체크 질문을 직접 생성하는 기능
- 방문 기록과 방문 완료
- 체크 기록 리비전과 교체 전 기록 복구
- 여러 매물 비교와 추천·점수
- 사진 순서 변경과 대표 사진 직접 지정
- 관리자 전용 화면
- 회원 탈퇴와 삭제 데이터 복구

## 2. 기능 요구사항

### 회원·인증

- 비로그인 사용자는 서비스 소개와 활성 시스템 체크 항목을 조회할 수 있어야 합니다.
- 사용자가 첫 저장 작업을 시도하면 Google 로그인을 요청해야 합니다.
- 최초 로그인 시 별도 회원가입 없이 회원을 생성해야 합니다.
- 기존 회원이 다시 로그인하면 이전에 저장한 데이터를 계속 이용할 수 있어야 합니다.
- 로그인한 사용자는 자신의 이름과 이메일을 조회할 수 있어야 합니다.
- 사용자는 현재 기기에서 로그아웃할 수 있어야 합니다.
- 로그아웃 후에는 저장·수정·삭제와 개인 데이터 조회 기능을 사용할 수 없어야 합니다.
- 인증되지 않은 사용자가 보호된 API를 호출하면 인증 오류를 반환해야 합니다.
- 다른 사용자의 자원은 존재 여부를 노출하지 않고 찾을 수 없음으로 처리해야 합니다.

### 매물

- 로그인한 사용자는 후보 매물을 등록할 수 있어야 합니다.
- 매물 목록에서 대표 사진을 볼 수 있어야 합니다.
- 매물에는 이름, 보증금, 월세와 발견 경로를 입력할 수 있어야 합니다.
- 이름은 필수이고 나머지 기본 정보는 선택 사항이어야 합니다.
- 매물 목록에서 이름, 금액, 사진 미리보기와 체크 진행 현황을 확인할 수 있어야 합니다.
- 사용자는 생성일 또는 최근 갱신 기준으로 매물을 필터링할 수 있어야 합니다.
- 사용자는 매물 상세에서 기본 정보, 사진, 메모와 단계별 체크 기록을 확인할 수 있어야 합니다.
- 사용자는 전달한 매물 기본 정보 필드만 수정할 수 있어야 합니다.
- 사용자는 매물을 삭제하기 전에 클라이언트에서 삭제 영향을 확인할 수 있어야 합니다.
- 매물을 삭제하면 사진 객체, 메모, 단계별 체크 기록과 체크 결과도 함께 삭제해야 합니다.

### 사진

- 사진이 없으면 기본 이미지를 표시해야 합니다.
- 사용자는 자신의 매물에 사진을 업로드할 수 있어야 합니다.
- 사진은 업로드에 성공한 순서대로 표시해야 합니다.
- 사용자는 대표 사진을 직접 지정할 수 있습니다.
- 사용자는 등록한 사진을 삭제할 수 있어야 합니다.
- 외부 파일 저장과 DB 메타데이터 저장 중 하나라도 실패하면 사진이 등록된 것으로 표시하면 안 됩니다.

### 매물 메모

- 매물마다 기본 메모와 추가 메모 하나를 제공해야 합니다.
- 사용자는 추가 메모를 작성하거나 삭제할 수 있어야 합니다.
- 기본 메모와 자유 메모는 하나의 저장 요청으로 전체 교체해야 합니다.

### 시스템 체크 항목

- 시스템 체크 항목은 온라인·전화, 현장, 계약 전 중 하나의 단계에 속해야 합니다.
- 시스템 체크 항목은 핵심 항목과 선택 항목으로 구분해야 합니다.
- 핵심 항목은 같은 단계의 사용자 체크리스트에 반드시 포함해야 합니다.
- 선택 항목은 사용자가 검색해 체크리스트에 추가하거나 제거할 수 있어야 합니다.
- 새로운 핵심 항목이 등록돼도 기존 사용자 체크리스트에는 영향을 주면 안 됩니다.
- 비활성화된 항목은 새로운 체크리스트에 추가할 수 없어야 합니다.
- 이미 사용자 체크리스트에 포함된 항목이 비활성화돼도 해당 체크리스트에서는 유지해야 합니다.
- 이미 매물에 복사된 질문과 순서는 시스템 항목 변경의 영향을 받지 않아야 합니다.

### 사용자 체크리스트

- 사용자는 온라인·전화, 현장, 계약 전 중 하나의 단계를 선택해 체크리스트를 생성할 수 있어야 합니다.
- 생성할 때 해당 단계의 핵심 항목을 모두 자동으로 포함해야 합니다.
- 사용자는 같은 단계의 선택 항목을 추가할 수 있어야 합니다.
- 사용자는 핵심 항목을 사용자 체크리스트에서 제거할 수 있습니다.
- 동일한 시스템 항목을 하나의 체크리스트에 중복해서 포함할 수 없어야 합니다.
- 사용자는 모든 항목의 표시 순서를 변경할 수 있어야 합니다.
- 사용자는 자신의 체크리스트 목록과 상세를 조회할 수 있어야 합니다.
- 사용자는 체크리스트 이름과 전체 항목 순서를 수정할 수 있어야 합니다.
- 생성 후 체크리스트 단계는 변경할 수 없어야 합니다.
- 사용자는 체크리스트를 삭제할 수 있어야 합니다.
- 삭제된 체크리스트는 목록·상세·수정·신규 적용 대상에서 제외해야 합니다.
- 체크리스트를 삭제해도 이미 매물에 복사된 체크 기록은 유지해야 합니다.

### 매물 체크 기록

- 하나의 매물은 각 단계에 체크리스트를 최대 하나 적용할 수 있어야 합니다.
- 적용 시 이름, 단계, 시스템 항목 ID, 질문과 순서를 매물 체크 기록으로 복사해야 합니다.
- 새로 적용된 모든 항목은 미확인 상태와 빈 메모로 시작해야 합니다.
- 사용자는 매물의 단계별 적용 현황과 상태별 항목 수를 조회할 수 있어야 합니다.
- 사용자는 적용된 질문, 확인 상태와 항목별 메모를 조회할 수 있어야 합니다.
- 원본 체크리스트 수정은 기존 매물 체크 기록에 자동 반영하면 안 됩니다.
- 사용자는 같은 단계의 다른 체크리스트로 기존 체크리스트를 교체할 수 있어야 합니다.
- 교체 시 동일한 시스템 항목 ID를 가진 항목은 상태와 메모를 유지해야 합니다.
- 새 체크리스트에만 있는 항목은 미확인 상태와 빈 메모로 추가해야 합니다.
- 새 체크리스트에 없는 기존 항목과 결과는 현재 기록에서 제거해야 합니다.
- 교체 전 제거된 기록은 복구하거나 별도 이력으로 조회할 수 없어야 합니다.

### 체크 상태와 항목 메모

- 체크 상태는 `UNCONFIRMED`, `GOOD`, `CAUTION`으로 통일해야 합니다.
- 새 항목의 기본 상태는 `UNCONFIRMED`여야 합니다.
- 사용자는 상태를 언제든 다시 변경할 수 있어야 합니다.
- 사용자는 항목별 메모를 작성·수정·삭제할 수 있어야 합니다.
- 상태와 메모는 서로 독립된 API로 처리해야 합니다.
- 같은 항목의 같은 API 저장 요청은 클라이언트가 순서대로 처리해야 합니다.

### 진행 현황

- `GOOD`과 `CAUTION`을 확인 완료로 계산해야 합니다.
- `UNCONFIRMED`는 확인 완료에 포함하지 않아야 합니다.
- 단계별로 전체·확인 완료·괜찮음·주의·미확인 항목 수를 제공해야 합니다.
- 매물에 적용된 모든 단계의 전체 현황을 제공해야 합니다.
- 진행률은 `확인 완료 항목 수 ÷ 전체 항목 수 × 100`의 정수 값이어야 합니다.
- 전체 항목이 없으면 진행률은 0이어야 합니다.

## 3. 비기능 요구사항

- 운영 환경의 모든 통신은 HTTPS를 사용해야 합니다.
- 토큰, Google 인증 정보, 사진 저장 키와 개인정보를 일반 로그에 기록하면 안 됩니다.
- 모든 개인 데이터 조회·수정·삭제에서 소유자를 검증해야 합니다.
- 사진 업로드를 제외한 단건 API는 정상 부하에서 서버 처리 시간 p95 500ms 이하를 목표로 합니다.
- 체크리스트 생성·수정·삭제, 매물 적용·교체와 매물 삭제는 각각 하나의 트랜잭션으로 처리해야 합니다.
- 사진 객체 저장 후 DB 저장이 실패하면 객체를 보상 삭제해야 합니다.
- 요청 ID, API 경로, 상태 코드와 처리 시간을 구조화 로그로 남겨야 합니다.
- 날짜와 시간은 ISO 8601 UTC 문자열, 금액은 원 단위 정수, 문자는 UTF-8로 처리해야 합니다.
- 구현된 API는 OpenAPI JSON과 Swagger UI로 제공해야 합니다.

## 4. 완료 기준

- 비로그인 사용자가 시스템 체크 항목을 둘러볼 수 있습니다.
- 사용자가 Google 로그인 후 매물·사진·메모·체크리스트를 관리할 수 있습니다.
- 핵심·선택 항목으로 사용자 체크리스트를 구성할 수 있습니다.
- 체크리스트를 매물 단계에 적용하고 당시 항목이 사본으로 보존됩니다.
- 체크리스트 교체 시 공통 항목의 상태·메모가 유지되고 제거 항목은 삭제됩니다.
- 상태와 메모가 독립적으로 자동 저장되고 서로의 값을 변경하지 않습니다.
- 사용자 체크리스트 삭제 후에도 기존 매물 체크 기록이 조회됩니다.
- 다른 사용자의 모든 개인 자원 접근이 차단됩니다.
- Swagger UI와 OpenAPI JSON이 API 명세와 일치합니다.

## 5. 전달 정책

### 매물

- 회원당 최대 30개까지 등록하며 동시 생성에서도 제한을 지키기 위해 회원 행을 잠급니다.
- 이름은 trim 후 1~30자입니다.
- 보증금·월세·관리비는 0 이상의 정수입니다.
- 주소와 발견 경로는 선택이며 최대 500자입니다.
- 매물 수정은 전체 필드를 변경합니다.
- 기본 정렬은 `lastActivityAt DESC`, `propertyId DESC`입니다.
- 메모와 체크 결과 변경도 최근 활동 시각을 갱신합니다.
- 매물 삭제 시 연결된 DB 데이터는 개발자가 직접 삭제합니다.

### 매물 메모

- 매물 하나에 자유 메모는 최대 하나입니다.
- 기본 메모와 자유 메모를 한 요청으로 전체 교체합니다.
- 기본 항목 내용은 최대 100자, 자유 메모는 최대 2,000자입니다.

### 시스템 체크 항목

- 단계는 `ONLINE_PHONE`, `ON_SITE`, `PRE_CONTRACT`입니다.
- 유형은 `CORE`, `OPTIONAL`이며 기본 템플릿이 `CORE`입니다.
- 단계는 필수 검색 조건이고 질문 검색어는 선택 조건입니다.
- 조회 시 `CORE`를 `OPTIONAL`보다 먼저 위치합니다.
- 비활성 항목은 신규 체크리스트에 추가할 수 없지만 기존 체크리스트에서는 유지·재정렬할 수 있습니다.
- 시스템 항목 변경은 이미 매물에 적용된 스냅샷에 영향을 주지 않습니다.

### 사용자 체크리스트

- 회원 본인의 체크리스트만 관리할 수 있습니다.
- 이름은 trim 후 1~30자이고 항목은 최소 1개, 최대 30개입니다.
- 같은 시스템 항목을 중복하거나 다른 단계의 항목을 넣을 수 없습니다.
- 생성 시 해당 단계의 활성 `CORE`를 자동 포함합니다.
- `CORE`를 먼저 배치하고 사용자가 선택한 나머지 항목의 상대 순서를 유지합니다.
- 수정은 이름과 전체 항목 배열을 한 번에 교체합니다.
- 체크리스트를 삭제해도 이미 매물에 적용된 기록은 유지합니다.

### 매물 적용 체크리스트

- 매물마다 단계별 체크리스트를 최대 하나 적용할 수 있습니다.
- 적용할 사용자 체크리스트는 매물과 같은 회원 소유여야 합니다.
- 원본 체크리스트 ID·이름·단계와 시스템 항목 ID·질문·메모·상태·순서를 스냅샷으로 저장합니다.
- 원본이 변경돼도 기존 스냅샷은 자동 변경되지 않습니다.
- 교체할 때 같은 시스템 항목 ID의 상태와 메모만 승계합니다.
- 새 항목은 `UNCONFIRMED`와 빈 메모로 시작하고 빠진 항목은 삭제합니다.
- 교체 시 모든 적용 항목에 새로운 ID를 발급합니다.

### 체크 결과와 진행률

- 상태는 `UNCONFIRMED`, `GOOD`, `CAUTION`입니다.
- 상태와 메모는 독립된 API와 SQL로 저장하고 항목 메모는 최대 500자입니다.
- 서버에는 마지막으로 정상 처리된 요청이 최종 상태로 남습니다.
- `GOOD`과 `CAUTION`을 완료로 집계하고 전체가 0이면 진행률은 0입니다.
- 매물 목록·상세는 모든 단계 결과를 합산하고 단계 화면은 단계별 진행률을 제공합니다.

### 사진

- 매물당 최대 30장, 한 장당 최대 5MiB를 권장합니다.
- JPG, JPEG, PNG, WebP, HEIC를 허용합니다.
- 업로드 완료 시각과 ID 순으로 표시합니다.
- 대표 사진을 추가할 수 있습니다.

## 원문 안에서 확인된 충돌

- 대표 사진 직접 지정은 제외와 포함 양쪽에 적혀 있습니다.
- 핵심 항목은 반드시 포함과 사용자 제거 허용 양쪽에 적혀 있습니다.
- 매물 수정은 전달 필드만 수정과 전체 교체 양쪽에 적혀 있습니다.
- 선택 금액의 `NULL`과 기본값 `0`의 의미가 분리되지 않았습니다.
- 주소·관리비·최근 활동 정책은 전달 데이터 모델과 완전히 맞지 않습니다.

MVP2의 채택 결과는 원문을 고치지 않고 [결정 대장](../decisions/README.md)에 기록합니다.
