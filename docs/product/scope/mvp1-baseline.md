## 구현된 기능

### 회원·인증

- Google OAuth authorization code를 백엔드가 교환·검증하고 이메일로 회원을 생성하거나 갱신합니다.
- HS256 JWT access token을 발급하며 기본 유효 시간은 12시간입니다.
- 보호 API는 bearer token을 요구하고 회원 ID를 주입합니다.
- 로그인 회원은 `/api/members/me`로 이름과 이메일을 조회합니다.
- 로그아웃은 프론트엔드 메모리 세션을 제거합니다.
- 시스템 체크 항목 조회는 인증 없이 가능합니다.

구현 한계는 access token을 브라우저 메모리에만 보관한다는 점입니다. 새로고침이나 탭 종료 뒤 로그인 상태를 복구하는 refresh token·쿠키 세션은 없습니다.

### 매물

- 회원 소유 매물의 생성·목록·상세·전체 수정·삭제를 제공합니다.
- 회원 행을 잠근 뒤 개수를 세어 회원당 최대 30개를 보장합니다.
- 이름은 trim 후 1~30자, 발견 경로는 최대 500자입니다.
- 보증금과 월세는 입력하지 않아도 도메인에서 `0`으로 정규화됩니다.
- 수정은 `PUT`으로 이름·보증금·월세·발견 경로를 전체 교체합니다.
- 목록은 `property_id DESC`입니다. 최근 활동 시각과 주소·관리비는 없습니다.
- 다른 회원의 매물은 찾을 수 없음으로 응답합니다.
- 삭제 서비스가 메모·체크 기록·사진 메타데이터를 순서대로 지운 뒤 매물을 삭제합니다.

### 사진

- 사진 목록·인증된 콘텐츠 조회를 위한 응답 구조, 삭제와 대표 사진 지정이 구현되어 있습니다.
- 업로드 시각과 ID 순으로 조회하고 대표 사진이 없으면 가장 오래된 사진을 자동 지정합니다.
- 매물당 30장, 파일당 5MiB, JPEG·PNG·WebP·HEIC·HEIF 검증 코드가 있습니다.
- 대표 사진 지정 API와 프론트엔드 별 버튼이 이미 존재합니다.

그러나 실제 파일 업로드 백엔드 엔드포인트와 객체 저장 서비스는 구현되지 않았습니다. 프론트엔드에는 업로드 호출이 있지만 MVP1 테스트도 이를 미구현 응답으로 취급합니다.

### 매물 메모

- 활성 시스템 메모 항목을 매물 메모 스냅샷으로 초기화합니다.
- 구조화 메모 항목과 자유 메모를 조회하고 한 요청에서 전체 저장합니다.
- 구조화 항목은 최대 20개, 내용은 100자, 자유 메모는 2,000자입니다.

### 시스템·사용자 체크리스트

- 단계는 `ONLINE_PHONE`, `ON_SITE`, `PRE_CONTRACT`, 상태는 `UNCONFIRMED`, `GOOD`, `CAUTION`입니다.
- 시스템 항목은 `CORE`, `OPTIONAL`이며 단계·검색어로 조회합니다.
- 사용자 체크리스트 생성 시 해당 단계의 활성 `CORE`를 자동 포함합니다.
- 생성·수정 시 1~30개, 동일 단계, 중복 없음과 소유자를 검증합니다.
- 수정은 이름과 전체 항목 배열을 교체하며 단계는 변경하지 않습니다.
- 사용자 체크리스트 삭제 시 원본 FK는 `ON DELETE SET NULL`이 되어 기존 매물 스냅샷을 유지합니다.

`CORE`는 생성 시 자동 포함하지만 수정 요청에서는 전체 항목 배열을 받아 검증하므로 사용자가 제거할 수 있습니다.

### 매물 체크 기록과 진행률

- 매물의 단계마다 체크리스트를 하나 적용하거나 교체합니다.
- 적용 당시 체크리스트 이름·단계와 항목 ID·유형·질문·순서를 복사합니다.
- 교체 시 동일한 시스템 항목 ID의 상태와 메모를 승계합니다.
- 상태와 메모를 독립된 `PATCH` API로 저장합니다.
- 전체·완료·괜찮음·주의·미확인 개수를 단계별·매물 전체로 집계합니다.
- `GOOD`과 `CAUTION`을 완료로 계산하고 전체가 0이면 진행률을 0으로 처리합니다.

## 화면과 라우트

MVP1 프론트엔드에는 로그인, 매물 목록·등록·상세·수정·사진·메모, 체크리스트 홈·목록·생성·상세, 매물 적용·진행, 마이페이지가 있습니다. 비교·내보내기·팁은 예정 화면만 있습니다.

## 구현과 전달 문서가 다른 부분

| 항목 | 전달 문서 | 실제 구현 |
| --- | --- | --- |
| 로그인 유지 | 기기를 바꿔도 기록 유지, 로그인 상태 유지 | 기록은 서버에 유지하지만 access token은 메모리 전용 |
| 사진 업로드 | 포함 | 백엔드 업로드 미구현 |
| 대표 사진 지정 | 제외와 포함이 충돌 | 직접 지정 구현 |
| 매물 수정 | 부분 수정과 전체 교체가 충돌 | 전체 교체 |
| 선택 금액 | `NULL` 또는 기본값 0 | 도메인에서 0으로 정규화 |
| 기본 정렬 | 최근 활동 | ID 내림차순 |
| 주소·관리비 | 정책에 존재 | 미구현 |
| 최근 활동 시각 | 정책에 존재 | 미구현 |
| `CORE` 제거 | 상충 | 수정 시 제거 가능 |
| 회원 마지막 로그인 | 전달 ERD에 존재 | 컬럼 미구현 |

## MVP2가 반드시 메워야 하는 기준선 결손

- 실제 사진 업로드와 객체 저장 보상 처리
- 로컬에서 외부 키 없이 체험할 수 있는 인증·지도 데모 모드
- 주소·좌표와 최근 활동 정렬
- 와이어프레임의 대표 사진, 빈 상태, 지도와 주변 분석
- API·DB·화면 정책의 단일 결정 대장
