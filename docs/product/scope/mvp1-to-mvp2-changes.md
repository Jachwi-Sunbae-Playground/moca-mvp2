## 도메인 기준 변경

### 인증

- 운영 Google OAuth는 유지합니다.
- 로컬 기본은 데모 로그인으로 두되 운영 프로필에서는 활성화할 수 없습니다.
- MVP2 v1에서도 refresh token은 도입하지 않고 새로고침 시 세션 복구는 `sessionStorage`를 사용합니다. 민감도와 속도를 고려해 12시간 access token과 만료 시각만 저장합니다.

### 매물

- `address`, `road_address`, `latitude`, `longitude`, `last_activity_at`을 추가합니다.
- 관리비는 MVP2 매물 기본 필드로 추가하지 않고 기본 메모 양식에서 기록합니다.
- 금액 미입력은 기존 호환을 위해 0으로 저장하되 응답에서 0을 미입력처럼 표시할지는 프론트가 결정합니다.
- 목록 기본 정렬을 최근 활동 시각, ID 내림차순으로 바꿉니다.

### 사진

- MVP1에서 빠진 업로드를 완성합니다.
- 매물당 30장, 파일당 5MiB를 실제 제한으로 적용합니다.
- 브라우저 호환을 위해 MVP2 v1 업로드는 JPEG·PNG·WebP만 허용합니다. HEIC·HEIF는 서버 변환을 구현하기 전까지 오류로 안내합니다.
- 첫 사진은 대표가 되고 사용자가 다른 사진을 지정할 수 있습니다.

### 체크리스트

- 스냅샷·교체·집계 정책은 유지합니다.
- `CORE`는 생성 시 기본으로 넣지만 사용자가 편집 화면에서 제거할 수 있습니다.
- 사용자가 시스템에 없는 새 질문을 직접 만드는 기능은 계속 제외합니다.

### 지도

- 장소 데이터는 저장하지 않고 요청 시 조회합니다.
- 매물 주소와 좌표만 저장합니다.
- 주변 분석은 Kakao Local 응답을 짧게 캐시하며 장애 시 마지막 화면을 유지하고 재시도 안내를 표시합니다.

## 기준선에서 발견한 구현 결손

- 사진 업로드 백엔드가 없습니다.
- 대표 사진 테이블의 현재 UNIQUE 제약은 매물당 한 장을 DB 수준에서 보장하지 못합니다.
- 일부 하위 테이블 삭제는 애플리케이션 순서에 의존하고 FK cascade가 일관되지 않습니다.
- `last_activity_at`이 없어 최신순 요구를 충족하지 못합니다.
- access token 메모리 저장은 새로고침 뒤 로그인 상태를 유지하지 못합니다.

다음 구현은 이 결손을 버그·기반 작업으로 먼저 해결한 뒤 화면 순서대로 진행합니다.
