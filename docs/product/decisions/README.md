# MVP2 제품·구현 결정 대장

- 상태: 구현 기준 v1

## 사용 방법

MVP2는 빠르게 실행 가능한 결과를 우선합니다. 비차단적인 모호함은 아래 기본 결정을 따르고 구현 중 새 결정은 다음 번호로 추가합니다. 사용자가 결과를 사용한 뒤 방향을 바꾸면 기존 행을 지우지 않고 상태를 `대체됨`으로 바꾼 뒤 새 결정을 추가합니다.

| ID | 상태 | 결정 | 이유와 영향 |
| --- | --- | --- | --- |
| `PD-001` | 채택 | 자료 충돌 시 사용자 확정 결정 → 최종 와이어프레임 → 실제 MVP1 구현 → 전달 문서 → 추론 순으로 판단합니다. | 화면 의도와 실제 기준선을 모두 보존합니다. |
| `PD-002` | 채택 | 대표 사진을 사용자가 직접 지정합니다. | `03-1` 별 버튼과 이미 구현된 MVP1 API를 따릅니다. |
| `PD-003` | 채택 | `CORE`는 생성 시 자동 포함하지만 편집 시 제거할 수 있습니다. | 빠른 개인화와 현재 구현을 유지합니다. 최소 1개 제한은 지킵니다. |
| `PD-004` | 채택 | 매물 수정은 `PUT` 전체 교체이고 미입력 금액은 0입니다. | 현재 API·도메인과 맞추고 부분 수정의 모호함을 제거합니다. |
| `PD-005` | 채택 | 관리비는 매물 컬럼이 아니라 기본 메모 항목으로 둡니다. | 와이어프레임이 메모에 관리비를 배치하며 중복 저장을 피합니다. |
| `PD-006` | 채택 | 매물에 도로명·지번 주소와 WGS84 위도·경도를 저장합니다. | 지도 핀 복원과 주소 표시를 안정화합니다. |
| `PD-007` | 채택 | 생성·수정·사진·메모·체크 변경이 `lastActivityAt`을 갱신합니다. | 와이어프레임의 최신순을 정의합니다. |
| `PD-008` | 채택 | DB 종속 행은 FK cascade를 기본으로 하고 서비스가 객체 저장소 삭제를 조정합니다. | DB 누락 삭제를 줄이되 S3는 트랜잭션 밖 보상 처리가 필요합니다. |
| `PD-009` | 채택 | 사진은 30장·5MiB의 실제 제한이며 JPEG·PNG·WebP만 지원합니다. | HEIC 브라우저 호환과 서버 변환 비용을 MVP2 v1에서 제외합니다. |
| `PD-010` | 채택 | 지도·주소·주변 시설은 Kakao Maps와 Kakao Local REST API로 통일합니다. | 국내 주소 품질과 단일 계정 설정을 우선합니다. |
| `PD-011` | 채택 | 외부 연동은 `demo`와 `live` adapter로 분리하고 로컬 기본은 `demo`입니다. | 키 없이도 완성 화면과 흐름을 검증할 수 있습니다. |
| `PD-012` | 채택 | Kakao REST 키는 백엔드 전용이고 장소 응답은 10분 캐시합니다. | 키 노출과 쿼터 낭비를 줄입니다. |
| `PD-013` | 채택 | 기본체크리스트는 활성 `CORE`의 가상 preset이며 사용자 목록 행을 만들지 않고 바로 매물에 적용합니다. | 불필요한 개인 체크리스트 생성을 막습니다. |
| `PD-014` | 채택 | 비교표 받기는 추천 없는 CSV 내보내기입니다. | `01` 버튼을 최소 구현하면서 점수·판정 범위는 늘리지 않습니다. |
| `PD-015` | 채택 | 브라우저 세션 복구는 `sessionStorage` access token으로 하고 refresh token은 도입하지 않습니다. | MVP 속도와 새로고침 사용성을 절충합니다. |
| `PD-016` | 채택 | `13-1`의 기존 매물 핀은 `13-3` 주변 분석으로 이동합니다. | 최종 `.pen` 파일과 별도 화면 이미지를 따릅니다. |
| `PD-017` | 채택 | `03-3`을 매물 정보 수정의 공식 화면 번호로 사용합니다. | 파일명과 최종 `.pen` 표기를 통일합니다. |
| `PD-018` | 채택 | 주변 시설은 Kakao 장소 데이터만 사용하고 공공데이터포털 별도 연동은 보류합니다. | 첫 버전의 계정·키·장애 지점을 최소화합니다. 실시간 교통은 제외합니다. |
| `PD-019` | 채택 | 상세 API 계약은 구현 전 Markdown을 기준으로 하고 구현 후 생성 OpenAPI JSON을 실제 정본으로 전환합니다. | 계약 우선 설계와 Springdoc 실제 결과의 중복을 관리합니다. |
| `PD-020` | 채택 | 다음 구현 작업은 로컬 완성과 배포 준비까지만 수행하고 AWS 생성·실배포는 하지 않습니다. | 저장소 규칙과 사용자 선행 결정을 지킵니다. |
| `PD-021` | 채택 | Kakao 유료 API·비즈월렛을 자동 활성화하지 않습니다. | 비용 발생은 사용자의 별도 승인 대상입니다. 무료 쿼터 부족 시 데모 모드로 유지합니다. |
| `PD-022` | 채택 | `demo` 인증에서는 `00`의 주 버튼 문구를 `데모로 시작하기`로 바꾸고 같은 위치에서 데모 로그인을 실행합니다. | 별도 미설계 화면을 늘리지 않으면서 Google 로그인으로 오해하게 만들지 않습니다. |
| `PD-023` | 채택 | `13-3`의 `전체`는 반경 2km와 전체 카테고리로 필터를 초기화합니다. | 공급자에 무제한 조회를 요청하지 않고 `500m·1km·2km` 계약을 유지합니다. |
| `PD-024` | 채택 | 데모 시드는 회원 이메일을 기준으로 멱등하게 만들고 이미 매물이 있으면 사용자 데이터를 덮어쓰지 않습니다. | 로컬 재시작 때 샘플을 중복 생성하거나 사용자의 확인 데이터를 잃지 않습니다. |
| `PD-025` | 채택 | 사진 콘텐츠는 공개 URL·presigned URL 없이 소유자 검증 백엔드 endpoint로 전달합니다. | MinIO와 S3 버킷을 비공개로 유지하고 같은 프론트 계약을 사용합니다. |
| `PD-026` | 채택 | 지도에서 위치를 누르면 역지오코딩한 도로명·지번 주소와 좌표를 매물 폼으로 전달합니다. | `13-2 → 02` 흐름에서 주소 문자열과 핀 위치가 어긋나지 않게 합니다. |
| `PD-027` | 채택 | 새 사용자 체크리스트는 시작 방식 선택 없이 해당 단계의 원룸 제공 항목을 즉시 불러오며 빈 목록 시작은 제공하지 않습니다. | 체크리스트 탭과 매물의 세 단계 진입에서 반복 선택을 없애고 생성 흐름을 한 가지로 통일합니다. |

## 구현 중 멈춰야 하는 경우

다음은 비차단 결정으로 처리하지 않습니다.

- 결제·과금 또는 유료 API 활성화
- 실제 AWS 자원 생성·도메인 연결·외부 배포
- 개인정보 처리 범위를 넓히는 기능
- 복구하기 어려운 데이터 삭제나 저장소 이력 재작성

그 밖의 UI 세부값·오류 문구·기술 구현 선택은 구현자가 진행하고 이 대장에 기록합니다.
