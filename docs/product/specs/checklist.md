# 체크리스트 명세

- 상태: 구현 기준 v1
- 관련 화면: `04`, `05`, `06`, `07`, `08`, `09`

## 시스템 항목과 단계

- `REQ-CHECK-001`: 단계는 `ONLINE_PHONE`, `ON_SITE`, `PRE_CONTRACT`입니다.
- `REQ-CHECK-002`: 시스템 항목은 `CORE`, `OPTIONAL`이고 활성 항목만 신규 선택에 노출합니다.
- `REQ-CHECK-003`: 단계와 선택 검색어로 시스템 항목을 찾고 사용자가 임의 질문을 새로 만들 수는 없습니다.

## 사용자 체크리스트

- `REQ-CHECK-004`: 로그인 회원은 단계별 체크리스트를 생성·조회·수정·삭제합니다.
- `REQ-CHECK-005`: 생성은 활성 `CORE`를 자동 포함하고 사용자가 선택한 `OPTIONAL`을 이어 붙입니다.
- `REQ-CHECK-006`: 편집 화면에서 이름·항목 포함 여부·전체 순서를 바꾸고 한 번에 저장합니다.
- `REQ-CHECK-007`: 이름은 trim 후 1~30자, 항목은 1~30개이며 중복·다른 단계 항목을 허용하지 않습니다.
- `REQ-CHECK-008`: `CORE`는 시작점일 뿐 저장 강제가 아니므로 사용자가 제거할 수 있습니다.

## 매물 적용

- `REQ-CHECK-009`: 한 매물은 단계별 체크리스트를 최대 하나 적용합니다.
- `REQ-CHECK-010`: 선택 화면은 내 체크리스트와 활성 `CORE`로 구성한 가상 `기본체크리스트`를 함께 보여줍니다.
- `REQ-CHECK-011`: 기본체크리스트 적용은 별도 사용자 체크리스트를 만들지 않고 현재 활성 `CORE`를 곧바로 매물 스냅샷으로 복사합니다.
- `REQ-CHECK-012`: 사용자 체크리스트 적용은 이름·단계·시스템 ID·유형·질문·순서를 복사합니다.
- `REQ-CHECK-013`: 교체 시 동일 시스템 ID의 상태와 메모를 승계하고 빠진 항목은 현재 기록에서 제거합니다.

## 정책

- `POL-CHECK-001`: 사용자 체크리스트 단계는 생성 후 변경할 수 없습니다.
- `POL-CHECK-002`: 비활성 시스템 항목도 기존 사용자·매물 스냅샷에서는 유지합니다.
- `POL-CHECK-003`: 사용자 체크리스트를 물리 삭제해도 매물 스냅샷은 원본 ID만 NULL로 바뀌고 유지됩니다.
- `POL-CHECK-004`: 교체 전 기록의 별도 이력과 복구는 제공하지 않습니다.
- `POL-CHECK-005`: 목록·편집·적용·삭제는 모두 소유자를 검증합니다.
- `POL-CHECK-006`: 새 사용자 체크리스트는 별도 시작 방식 선택 없이 해당 단계의 활성 `CORE`만 먼저 보여줍니다. 빈 목록으로 시작하는 기능은 제공하지 않고 활성 `OPTIONAL`은 체크 항목 추가 화면에서 선택합니다.
- `POL-CHECK-007`: 매물 상세의 단계 카드는 적용 여부와 관계없이 선택 화면으로 이동하며, 적용된 체크리스트가 있으면 현재 선택으로 표시합니다.

## 인수 기준

- 세 단계 각각 생성·편집·삭제·적용·교체가 가능합니다.
- `04-E1`, `04-E2`, `07-E`, `08-E`, `09-E` 빈 상태의 CTA가 와이어프레임 흐름으로 이동합니다.
- 원본을 수정·삭제해도 이미 매물에 적용된 질문과 결과가 바뀌지 않습니다.
