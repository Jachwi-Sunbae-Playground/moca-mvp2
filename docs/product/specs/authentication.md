# 인증 명세

- 상태: 구현 기준 v2
- 관련 화면: `00`, `10`

## 요구사항

- `REQ-AUTH-001`: 사용자는 외부 계정 연결 없이 닉네임과 선택 비밀번호로 시작합니다.
- `REQ-AUTH-002`: 처음 쓰는 닉네임은 회원을 만들고, 이후 같은 정규화 닉네임은 같은 회원 데이터로 연결합니다.
- `REQ-AUTH-003`: 비밀번호를 비워 만든 닉네임은 보호되지 않으며 같은 닉네임을 입력한 누구나 매물·사진·메모·체크 기록을 조회·수정·삭제할 수 있습니다.
- `REQ-AUTH-004`: 처음 닉네임을 만들 때 비밀번호를 입력하면 보호되며 이후에는 같은 비밀번호가 있어야 시작할 수 있습니다.
- `REQ-AUTH-005`: 로그인 후 매물 목록으로 이동하고 마이페이지에서 닉네임과 비밀번호 보호 여부를 확인합니다.
- `REQ-AUTH-006`: 로그아웃하면 token과 개인 query cache를 제거하고 로그인 화면으로 이동합니다.
- `REQ-AUTH-007`: 인증되지 않은 보호 API는 401, 다른 회원의 자원은 404로 처리합니다.

## 정책

- `POL-AUTH-001`: 기본 access token 유효 시간은 12시간입니다.
- `POL-AUTH-002`: MVP2 v2는 refresh token을 도입하지 않습니다.
- `POL-AUTH-003`: 브라우저 새로고침 복구를 위해 `sessionStorage`에 access token과 만료 시각을 보관합니다. 브라우저 종료 뒤에는 다시 시작합니다.
- `POL-AUTH-004`: 닉네임은 NFKC 정규화와 앞뒤 공백 제거 뒤 대소문자를 구분하지 않는 1~30자로 식별하며 제어 문자를 허용하지 않습니다.
- `POL-AUTH-005`: 선택 비밀번호는 4~64자이면서 UTF-8 기준 72바이트 이하여야 하고 BCrypt hash만 저장합니다.
- `POL-AUTH-006`: 보호하지 않고 만든 닉네임에 나중에 비밀번호를 붙일 수 없습니다. 보호 닉네임의 비밀번호 변경·찾기·복구도 MVP2 v2 범위에서 제공하지 않습니다.
- `POL-AUTH-007`: 보호 닉네임은 10분 동안 5회 실패하면 해당 닉네임의 추가 시도를 일시 제한합니다.
- `POL-AUTH-008`: token·원문 비밀번호·비밀번호 hash를 일반 로그에 기록하지 않습니다.
- `POL-AUTH-009`: 기존 Google 회원은 표시 이름을 보호되지 않은 닉네임으로 변환합니다. 정규화 이름이 겹치면 내부 회원 ID suffix를 붙여 데이터를 분리합니다.

## 인수 기준

- 외부 인증 키 없이 새 닉네임으로 시작하고 모든 개인 기능을 사용할 수 있습니다.
- 비밀번호가 없는 같은 닉네임은 같은 데이터를 공유하고, 비밀번호가 있는 닉네임은 올바른 비밀번호만 허용합니다.
- 비밀번호가 없는 닉네임을 비밀번호로 선점하거나 보호 닉네임을 반복 대입할 수 없습니다.
- 새로고침 뒤 같은 탭에서 세션을 복구하고 만료·401·로그아웃 뒤에는 보호 화면에 접근할 수 없습니다.
