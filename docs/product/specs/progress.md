# 진행 현황과 자동 저장 명세

- 상태: 구현 기준 v1
- 관련 화면: `01`, `03`, `05`

## 요구사항

- `REQ-PROGRESS-001`: 체크 상태는 `UNCONFIRMED`, `GOOD`, `CAUTION`입니다.
- `REQ-PROGRESS-002`: 새 항목은 `UNCONFIRMED`와 빈 메모로 시작합니다.
- `REQ-PROGRESS-003`: 상태와 항목 메모를 서로 독립된 API로 자동 저장합니다.
- `REQ-PROGRESS-004`: 단계별·매물 전체의 전체·완료·괜찮음·주의·미확인 수를 제공합니다.
- `REQ-PROGRESS-005`: 매물 상세에서는 세 단계 전체 집계와 함께 각 단계의 완료/전체·괜찮음·주의·미확인 집계를 해당 행에 표시합니다.
- `REQ-PROGRESS-006`: 매물 목록 카드는 전체 통합 바 대신 1·2·3단계를 따로 표시하고 적용하지 않은 단계는 `미적용`으로 구분합니다.

## 정책

- `POL-PROGRESS-001`: `GOOD`과 `CAUTION`이 완료이고 `UNCONFIRMED`는 미확인입니다.
- `POL-PROGRESS-002`: 진행률은 `floor(완료 ÷ 전체 × 100)`이며 전체가 0이면 0입니다.
- `POL-PROGRESS-003`: 같은 항목의 같은 필드 요청은 프론트엔드가 직렬화하고 서로 다른 필드는 독립적으로 보냅니다.
- `POL-PROGRESS-004`: 서버에서 마지막으로 성공해 커밋된 요청이 최종 값입니다.
- `POL-PROGRESS-005`: 항목 메모는 500자 이하이고 빈 문자열은 삭제와 같습니다.
- `POL-PROGRESS-006`: 상태 또는 메모 저장 성공은 매물 최근 활동 시각을 갱신합니다.

## 인수 기준

- 상태 변경은 메모를, 메모 변경은 상태를 덮어쓰지 않습니다.
- 저장 중·성공·실패를 항목 단위로 확인하고 실패 뒤 재시도할 수 있습니다.
- 목록·상세·단계 집계가 같은 원본 행으로 계산되어 서로 일치합니다.
- 어떤 단계만 사용해도 다른 단계의 미적용이 미완료로 합산되지 않습니다.
