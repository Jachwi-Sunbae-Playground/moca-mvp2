# 이슈와 PR

## 이슈

### 제목

```text
[영역] 작업 내용
```

예시:

```text
[BE] 지도 검색 기능을 구현한다
[Infra] 최소 배포 기반을 준비한다
[Docs] MVP2 정책을 정리한다
```

### 본문

```markdown
## 배경
<!-- 이 작업이 필요한 이유와 해결하려는 문제를 작성 -->

## 작업 내용

구현해야 할 내용을 작성합니다.

- [ ] 

## 완료 조건

작업이 완료됐다고 판단할 수 있는 기준을 작성합니다.

- [ ] 

## 참고 자료

관련 문서, 정책 출처, 디자인, API 명세 또는 선행 Issue를 연결합니다.

- 관련 문서:
- 선행 Issue:
- 후속 Issue:
```

이 양식은 [`.github/ISSUE_TEMPLATE/issue.md`](../../.github/ISSUE_TEMPLATE/issue.md)에 등록되어 있어 Issue를 생성하면 자동으로 채워진다. 양식을 바꾸면 이 문서와 템플릿 파일을 같은 PR에서 수정한다.

## PR

- PR에는 변경 목적, 주요 결정과 테스트 결과를 명시한다.
- 하나의 PR에는 하나의 목적만 담는다.
- 작업 브랜치의 코드는 PR을 통해 `main`으로 병합한다.
- 저장소 변경이 없는 조사와 외부 설정은 Issue 체크리스트와 댓글에 결과를 남긴다.
- 큰 작업은 추적 Issue 아래에 독립적으로 완료할 수 있는 하위 Issue를 연결한다.

### 제목

```text
<type>: 변경 내용을 작성한다
```

예시:

```text
feat: 지도 검색 기능을 구현한다
chore: 최소 배포 기반을 준비한다
docs: MVP2 정책을 정리한다
```

### 본문

```markdown
## 🔗 관련 이슈
<!-- 이 PR이 해결하는 이슈 -->
Related to #

## 작업 내용

- 구현하거나 변경한 내용을 작성합니다.

## 고민한 점

- 구현 과정에서 고민한 부분과 선택 이유를 작성합니다.

## 리뷰 요청 사항

- 중점적으로 봐주었으면 하는 부분을 작성합니다.

## 테스트

- [ ] 기존 테스트가 통과합니다.
- [ ] 변경 사항에 대한 테스트를 작성했습니다.
```

이 양식은 [`.github/pull_request_template.md`](../../.github/pull_request_template.md)에 등록되어 있어 PR을 생성하면 자동으로 채워진다. 양식을 바꾸면 이 문서와 템플릿 파일을 같은 PR에서 수정한다.

## 머지

기본적으로 `Squash and merge`를 사용한다.

다음 조건을 만족한 후 머지한다.

- CI 성공
- 충돌 없음
- 작성자의 변경 파일 확인 완료

머지 후 작업 브랜치는 삭제한다.
