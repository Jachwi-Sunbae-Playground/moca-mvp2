# Git·GitHub 컨벤션

## Issue와 PR의 역할

- Issue에는 해결할 문제, 배경, 범위와 완료 조건을 기록한다.
- PR에는 실제로 선택한 해결 방법, 변경 내용, 검증 결과와 리뷰 포인트를 기록한다.
- 문제와 완료 조건은 일부 겹칠 수 있지만 PR 본문에 Issue 전체를 복사하지 않는다.
- PR에서 `Closes #이슈번호`로 연결한다.

## 제목

Issue와 PR 제목은 무엇을 다루는지 한 문장으로 작성한다. 커밋 제목은 다음 형식을 기본으로 한다.

```text
<type>: <변경 요약>
```

| type | 용도 |
| --- | --- |
| `feat` | 기능 추가 |
| `fix` | 버그 수정 |
| `refactor` | 동작을 바꾸지 않는 구조 개선 |
| `test` | 테스트 추가·수정 |
| `docs` | 문서 변경 |
| `chore` | 빌드·설정·도구 변경 |

## 커밋과 PR

- 커밋 하나에는 리뷰 가능한 하나의 논리적 변경을 담는다.
- 작업 중에는 Draft PR을 사용하고 리뷰 준비가 끝나면 Ready로 전환한다.
- PR 본문에는 `변경 내용`, `선택 이유`, `검증 방법`, `리뷰 요청 사항`을 작성한다.
- 관련 문서와 설정은 코드 변경과 같은 PR에서 수정한다.
- 필수 CI가 성공하고 최소 한 명의 승인을 받은 뒤 병합한다.
- 강제 푸시나 커밋 이력 변경이 필요하면 먼저 리뷰어와 공유한다.
